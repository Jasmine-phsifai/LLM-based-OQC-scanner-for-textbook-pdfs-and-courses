# 三课程真实计时（2026-09-07）

本轮是性能实测与上一轮改动说明，不是构建课程下载、生产存储迁移或新的公开去重 API。
用户更正原图数量为一千多张，并明确按每小时24–40张动态选择；50–80不是固定上限。
附件 `R:\archieve\AGENTS.md` 用作历史样例与未来格式的背景，不把其中的迁移指令
当成本轮要求；原始媒体只读，临时输入和识别正文不进入 Git。

## 上一轮改动及原问题严重性

OCRLLM 的提交 `feca47c` 主要补齐故障证据：安全的服务错误码和request ID
现在随checkpoint保存，恢复之后还能关联服务日志；HTTP504归类为timeout，
使调用方既有的重试策略按正确类别处理。此前可用的有限重试和断点恢复并非本轮
从零新增。这里没有证明整个库不可用或存在数据丢失；原问题会妨碍定位故障，
并使按timeout配置的策略无法正确处理504，属于生产可靠性缺陷。

Model Lab 的相关提交为 `3ca2805`、`33c632a`。主要修复进程、监听端口和health
身份核验，保留UNREADY但仍活着的受管进程记录，清理有准确归属证据的崩溃遗留
backend并支持restart。原先“端口还在、manager却说DISABLED”的状态在真实运行
中出现过，能阻断调用及可靠恢复，是无人值守生产的严重障碍。另将队列等待、
OCR上下文/输出/视觉预算等改为可验证配置，把永久context错误返回413，避免当作
临时503反复重试。ASR增加合作式生成时限，并在此次实现中补上EOS完整性校验；
不能据此倒推旧版已被证明经常把截断结果报成功。

上一轮有54项OCRLLM针对性测试、15项Model Lab测试，以及真实媒体、注入故障后的
重试/恢复和SIGKILL恢复验证。它证明协作和恢复路径，未证明整课准确率、张量批处理
或吞吐提升；可配置预算本身也不是加速成果。两仓依旧只通过HTTP协作，服务生命周期
留在Model Lab，选择、分批、重试和恢复留在OCRLLM。详见上一轮dated verification。

## 三组样例与计时口径

三组为同一课程相邻常规讲次，分别长 9677.568、9794.774、9788.097 秒，
相差不到两分钟，约 161–163 分钟。主代理检查每组八个均匀时点：均为正对黑板
及教师的正常机位，没有选用对着学生的错误机位。

原始截图 1210／1225／1224 张，包内 manifest 的全部时间戳逐项核验为 8 秒间隔。
图片读取、完整图像解码、灰度128×128和彩色32×32缩略图、现有 selector 选择、
选中图片复制分别计时。不含视频扫描或 FFmpeg 抽帧，因为样例已完成这一步。
当前没有接受预抽帧图片目录的公开 OCRLLM 去重入口，本轮 tools 桥接内部
`select_video_frame_candidates()`，保持原有 28–40 帧/小时目标与所有阈值不变。

用户在本轮明确纠正：按每小时24–40张动态选择，不能把所有课程固定截到80张。
因此OCR将识别现有核心自然选出的全部75／97／96张，分别约27.90／35.65／35.31张/小时。
原有核心28–40张/小时的目标没有改动，实际三组均满足用户24–40张/小时范围。
曾提出的80张benchmark截取方案已在任何正式OCR调用前撤销。

原音频为24 kHz单声道AAC/M4A，当前库只直接接受MP3。本轮临时转换为24 kHz
单声道64 kbps MP3，转换耗时 A/B/C 为20.354／20.379／20.363秒，原始文件hash
转换前后保持一致。这个适配成本计入整课音频端到端时间；不宣称已经原生支持AAC。
注意：上述24 kHz是转换后的整课输入，不是最终HTTP音频切片。现有
`materialize_long_audio_interval.py` 明确用 `-ar 16000 -ac 1 -b:a 64k -c:a libmp3lame`
重新编码每个片段，因此实际提交的是16 kHz单声道MP3；Model Lab也将非16 kHz
输入重采样到16 kHz。AAC转换本身不必降低采样率，这次下降来自库的明确参数。

识别复用公共 `batchify_images -> recognize_images_to_markdown` 和
`split_audio -> recognize_audio_to_markdown`，不替换库内部函数。真实 HTTP 和
subprocess 边界只包装计时，保留实际返回；没有模拟模型输出。音频10分钟纯逻辑
切片、无重复边界上下文；OCR每请求2图；单通道、每请求600秒上限；可恢复的
rate-limited/unavailable/timeout 各有一次额外重试、等待2秒。重试次数按真实记录算。

维护者明确正式OCR采用Model Lab既往`ocrllm-legacy`定制提示词，包括逐帧标记和
Mermaid/SVG/SMILES转写规则，并启用medium思考。原公共接口的`detail_ocr`实际是
另一份`board.v17`，故新增独立固定`course_ocr` / `course.legacy.v1`，将既有模板
原样迁入库并按每批原始文件名渲染。AST逐字比较模板一致；HTTP场景验证重试、
resume、state-loss repair、原始文件名和版本身份。不存在运行时跨仓import。
benchmark每次OCR请求记录实际prompt SHA256、字符数及image count，正文留在本机。

先集中处理三课ASR，再处理三课OCR；两种模型各自首次加载/预热单独计时，
三组正式计时均使用同模型驻留状态。原图从R卷读入，选中图和临时音频置于Linux
临时目录；不清空操作系统文件缓存。计时包含该运行方式的I/O、快照、解码、真实
物理音频切片和输出，而不是拿短片速度乘课程时长的估算。

GPU为RTX3090 24GiB，驱动610.88；ASR模型ID为`qwen3-asr-1.7b`，
OCR为`qwen3.8-27b-q6-k-medium-ocr`。正式识别wall计时不包含工具额外执行的
前后源文件hash核验及最后summary JSON写入，但包含库自身规划、快照、输出和
恢复开销；HTTP与FFmpeg时长是wall内部明细，不能再次相加到wall上。
`passed`只表示workflow complete且输入hash未变，不等于内容准确性通过。
NOSPEECH判定、失败片段和恢复调用需要另行列出。

OCR独立预热两图请求342.967秒，其中服务日志显示backend加载约321秒；HTTP200/stop，
2053输入/571输出tokens，182正文字符。实际llama进程参数为`--reasoning on
--reasoning-effort medium`。该预热不进入正式三组wall或均值。
ASR独立预热为一条30秒讲话片段，22.175秒、414输入/99输出tokens、163正文字符、
stop；该数包含加载及短片推理，不是纯加载时间，同样不进入三组正式均值。
